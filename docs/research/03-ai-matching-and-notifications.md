# AI条件ヒアリング・マッチング／通知チャネル 調査

> 2026-10-13 にサブエージェントが調べた結果をまとめたもの。LINEの料金とInstagramの制約は二次情報が混ざっているので、**実装の前に公式ドキュメントで確認すること**。

## A. AI条件ヒアリング

### モデルの使い分け
- 会話本体: `claude-sonnet-5-5`
- 物件の要約・通知文・推し理由: `claude-haiku-5-5`
- 「対応不可」になったときの代替提案の判断（将来の自律判断）: `claude-opus-5-5`

### ツール（tool use）
1. `update_criteria(patch, confidence, evidence_quote)` — 会話から条件の差分を出す。ユーザーの発言を根拠として引用させる
2. `ask_clarification(field, options[])` — あいまいな点を選択肢で聞き返す（UIではボタンとして表示）
3. `preview_matches(criteria_draft)` — 仮の条件でヒット件数を返す。「この条件だと3件、徒歩12分まで広げると18件」のように、緩めるか相談する材料にする
4. `confirm_criteria(summary)` — 確認カードを出し、ユーザーが承認したら条件の新しい版として保存する

- `confidence < 0.7` の項目は確認カードで「要確認」と表示する。**AIの推測だけで条件を確定させない**
- システムプロンプトとツール定義はプロンプトキャッシュに載せる。毎ターン、現在の条件JSONを先頭に入れる

### システムプロンプトの骨子（営業担当ペルソナ）
```
あなたは Devote の住まい探しコンシェルジュ。経験10年の不動産仲介営業として振る舞う。
- 条件は must / want に分類し、数値は理想値と許容幅を分けて聞く
- 1ターンの質問は最大2つ。予算・エリア・広さ・入居時期を優先する
- 数値の境界では「◯◯なら許容できますか？」と具体例で詰める（例: 70㎡希望→69.5㎡は？）
- 相場と乖離する条件は preview_matches の件数を根拠に柔らかく指摘し、代替案を出す
- 検討フェーズを会話から推定し、ゲージの調整を提案する
- 物件の存在・空室を断定しない。押し売り口調をしない
```

### スコアリング（ハイブリッド）
1. **ハードフィルタ**（SQLのWHERE）: must条件、掲載終了、対応不可
2. **ルールスコア**: 項目ごとの充足度（理想の範囲内なら1、許容幅の中では減点、外なら0）を重み付きで平均する
3. **埋め込み類似度**: 物件説明の埋め込みと、会話要約（暮らしのイメージ）の埋め込みのコサイン類似度。Claude API には埋め込みモデルがないので Voyage AI 等を使う
4. `score = α×rule + (1−α)×sem`（α=0.75 で始め、クリックや内見申込のログで調整する）

### ゲージ（検討フェーズ）
| フェーズ | 閾値 | 1回の件数 | 許容幅 |
|---|---|---|---|
| 情報収集 | 55 | 20 | 1.2倍に広げる |
| 比較検討 | 70 | 10 | そのまま |
| 内見済み | 82 | 3〜5 | want条件を must 扱いにする |
| 決断直前 | 90 | 2〜3 | 許容幅0 |

### 類似物件の推薦と学習
- 数値の特徴量ベクトル（`feature_vec vector(64)`）と説明文の埋め込み（`embedding`）で pgvector の近傍を探す → 最終スコアは `0.5×類似度 + 0.5×ユーザー条件スコア`
- **客付NGになった業者の物件は候補から外す**
- 管理者の判断（承認・却下・理由）とユーザーの反応を蓄積する → 段階的に自律化する: ①手動 → ②AIが下書きして管理者が承認 → ③承認率95%を超えた理由コードから自動化する

## B. 通知チャネル

### LINE Messaging API（メインのチャネル）
- LINE Login と Messaging API を**同じプロバイダー**の下に作る（userId を一致させるため）
- 料金（月額。公式ページで要確認）: コミュニケーション 0円/200通、ライト 5,000円/5,000通、スタンダード 15,000円/30,000通（追加配信が可能）。2026/10/1 から追加メッセージは1通3円（月20万通まで）
- push は通数に数えるが、reply は数えない → **ダイジェストにまとめて1通で送る**
- 物件カードは Flex Message の Carousel（最大12枚）。postback で「内見を問い合わせ」「興味なし」を受け取る
- 再試行で二重に送らないよう `X-Line-Retry-Key` ヘッダを使う。unfollow の Webhook を受けたら配信を止める

### Instagram（⚠ 定期通知には使えない）
- プロアカウントが必要。Metaアプリの権限（`instagram_business_manage_messages`）とアプリレビューが要る
- **ユーザーから先にDMしてもらう必要がある**
- **24時間ウィンドウ**: ユーザーの最後のメッセージから24時間を過ぎると送れない。HUMAN_AGENT タグ（7日まで延長）は人が手で返す用途に限られ、自動通知には使えない
- → **入口（集客）と会話型の通知に使う**。ユーザーがDMしてきたら24時間以内に新着を返し、定期通知はLINEかメールへ誘導する

### メール
- MVPは **Resend + React Email**。量が増えたら Amazon SES に移す（`EmailProvider` インターフェースで抽象化しておく）
- SPF/DKIM/DMARC、List-Unsubscribe（ワンクリック解除）は必須

### 通知頻度と重複防止
- 頻度は instant（5分のデバウンスで束ねる。深夜は保留）／ daily ／ weekly
- 送る前に `sent_ledger` へ `INSERT ... ON CONFLICT DO NOTHING` し、成功した物件だけ送る。値下げは `reason='price_down'` として別のキーにする
- 優先チャネルにだけ送る（LINE > メール > IG）。失敗したら次のチャネルにフォールバックする
- 送る直前に、掲載中であることと対応不可になっていないことを再確認する
- 物件の事実（賃料・面積など）はAIに書かせず、DBの値をテンプレートに差し込む

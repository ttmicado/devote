# 運用の約束と現在の状態

このリポジトリは複数の環境（別々の Claude セッション・人）から同時に変更される。
どの環境から作業を始めても、**まずこの文書を読んで現在の状態を把握し、運用に関わる変更をしたらこの文書を更新する**。
別環境の変更を取り込む・マージする前には、サブエージェント `ops-auditor`（手順はスキル `devote-operations`）で監査する。

- 会員サイトの画面・仕様の詳細: `docs/member-sites.md`
- デプロイ構成・Secrets: `docs/deploy.md`
- 構想: `docs/plan.md`

## 1. 巡回の全体像

| 項目 | 値 | 場所 |
|---|---|---|
| 定期実行 | 30分ごとに予定。GitHub の混雑で実際は数時間おきのこともある | `.github/workflows/crawl.yml` |
| crawl ジョブの制限時間 | 55分（強制終了の安全網） | 同上 `timeout-minutes` |
| 巡回全体の持ち時間 | 42分。残り8分を切ったら新しいソースを始めない | `packages/pipeline/src/cli.ts`（`DEVOTE_CRAWL_BUDGET_MINUTES`） |
| 1ソースの持ち時間 | 15分。過ぎたら取得済みの分を取り込んで終える | `packages/pipeline/src/crawl.ts`（`DEVOTE_SOURCE_MAX_MINUTES`） |
| 1ソースの詳細の上限 | 300件／回。超えた分・時間切れの分は次回 | `DEVOTE_MAX_DETAILS_PER_SOURCE` |
| 並列数 | 3サイト同時。同じサイトへのアクセスは直列 | `DEVOTE_CRAWL_PARALLEL` |
| 順番 | 会員サイト → 公開サイト（最後に成功してから長い順） | `crawlOrder`（`crawl.ts`） |
| notify ジョブ | crawl の成否にかかわらず実行（`if: always()`）。マッチング → 通知 | `crawl.yml` |
| DB マイグレーション | `packages/db/drizzle/**` を含む push で、**ブランチを問わず本番に適用**（`migrate.yml`）。Vercel のビルドでも実行 | `.github/workflows/migrate.yml` |

> **マイグレーションはマージ前に本番に入る。** PR のブランチに push した時点で本番の DB が変わるので、
> 古いコードのままでも壊れない変更（後方互換）にする。ロックのかかる変更は `SET LOCAL lock_timeout` を付ける。

## 2. 運用の約束（不変条件）

破る変更は、理由と合意なしに入れない。破りそうな変更は §3 の確認をする。

### 課金・回数（会員サイト）
- **レインズ**
  - 物件検索・物件詳細・図面の無料枠は、それぞれ月6,000件。社内の人と共有している。
  - 巡回は月4,500件までを日割りで使う（`REINS_MONTHLY_*_LIMIT`、`quota.ts` の `allowanceForRun`）。
  - 件数事前確認は無料なので、0件なら検索しない。ページ送りは件数に数えない（`pageTurnsAreFree`）。詳細は1件ごとに課金される。
  - 利用量は取得の直前に1件ずつ記録する（`onUsage`）。巡回の最後にまとめて記録しない。強制終了されると記録が漏れるため。
- **ATBB**: プランに検索回数の上限がある。2026-10-16 時点で残り72回（サイドバーの「残りプラン内検索可能数」）。調査を含めて、検索の実行は最小限にする。
- **ITANDI BB**: 1日3回・9〜21時・1検索あたり最大5ページ。これ以上増やさない（運営の注意喚起、規約第27条）。

### アカウントを守る（人と同じIDを使っている）
- ログイン失敗・追加認証・CAPTCHA は自動で突破しない。止まったら24時間待つ（`login-hold.ts`）。
- 同じIDが使用中（ATBB の ConcurrentLoginException）なら60分待つ。「強制終了させて利用する」は押さない。
- 巡回の最後に必ずログアウトする（`SiteAdapter.logout`、`crawlSource` の finally）。ATBB は ATBB 側 → ポータルの順に抜ける。ポータルだけ抜けると、次のログイン（人を含む）が「利用中」になる。
- 会員サイトの同時実行は1本（`maxConcurrency: 1`）。レインズは7〜23時以外は触らない。

### 公開範囲・写真・事実
- 会員サイト（レインズ・ATBB・ITANDI BB）にしか載っていない物件、または広告不可の物件は一般公開しない。提案を受けた会員にだけ見せる。
  - 会員サイトの一覧は `registry.ts` の `memberOnly` と `apps/web/lib/data.ts` の `MEMBER_ONLY_SOURCES` の2か所にある。一致はテストで確かめている。
- レインズの画像は保存しない（`imageUrls: []`）。他社の社名・ロゴ・透かしが入った写真は使わない（`noImageSourceIds`）。
- 物件の事実（賃料・面積・空室）は LLM に作らせない。
- 金額は円の整数で扱う。価格の列は bigint（21.4億円を超える売買物件があるため）。賃料の比較は管理費込みの総額で行う。

### データの正しさ
- 掲載終了の判定は、一覧を最後まで正常に巡回できた回だけ行う。次の場合は判定しない。
  - 差分検索（`partial`）
  - ブロックやエラーで一覧が不完全
  - 解釈できず飛ばした行がある（`ListPageResult.skipped`）
  - 時間切れ
  - 取り込みの失敗が半数以上
- 1件の解釈失敗・取り込み失敗でソース全体を止めない。その1件を警告に残して続ける。
- 会員サイトは、有効な希望条件の範囲（`crawlScopes`）だけを検索する。検索の回数は「エリア × 取引種別 × 物件種別」の掛け算で増える。
- 巡回をやめたソースは `retiredSourceIds` に入れて掲載を閉じる。巡回しないと掲載終了を判定できないため。
- 認証情報は `.env` と GitHub Secrets だけに置く。`storage/` はコミットしない。会員サイトのフィクスチャは会員名・担当者名・電話番号をマスクする。

## 3. 要注意の変更と確認すること

| 変更 | 確認すること |
|---|---|
| 対象エリア（`areas.ts`）・物件種別（`REINS_KINDS` 等）の追加 | レインズの検索回数（1回あたり・1日あたり）が日割りの枠に収まるか。詳細の待ち行列がどれだけ増えるか。巡回の持ち時間に収まるか |
| 会員サイトの件数・ページ数・頻度・期間を広げる | レインズの月4,500件、ITANDI の回数上限、ATBB の残り回数を計算し直す |
| ソースの追加 | 初回の取り込み量と1件あたりの所要時間（15分の持ち時間に対して）。`memberOnly` の付け忘れ。写真のロゴ・透かし。広告可否を取っているか。1行の解釈失敗で throw していないか |
| `memberOnly`・`isPubliclyListable`・通知の文面・SNS | 会員サイトの物件の文面・写真が一般公開の画面に出ないか |
| 写真の扱い（`noImageSourceIds` から外す、レインズの画像を取る） | 原則として却下 |
| ログイン・再試行・待ち時間 | アカウントロックにならないか。人の作業中のセッションを奪わないか。ログアウトしているか |
| 掲載終了の判定 | 差分検索・不完全な一覧で物件を誤って閉じないか |
| DB スキーマ | マージ前に本番に入る（§1）。古いコードでも動くか。ロック時間 |
| `crawl.yml` の時間・並列数・詳細の上限 | 55分の制限時間との関係。notify が遅れて「最速」が崩れないか |
